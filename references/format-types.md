# Carousel Format Types

Source: design.deb "LEARN DESIGN" framework + research synthesis. There are **5 distinct format archetypes** for an Instagram carousel. Pick ONE per carousel — mixing formats inside a single carousel kills clarity.

Use this reference at **Step 1.5 — Format choice** to ask the user which format fits their topic.

---

## The 5 Formats (verbatim from design.deb framework)

| # | Format | When to use | Example topic |
|---|---|---|---|
| **01** | **Comparison Format** | Two options, methods, or eras side-by-side | "Bad VS Beautiful Botox" / "Old Playbook vs New Playbook" |
| **02** | **Tutorial Format** | Step-by-step how-to in 5-10 slides | "Viral Carousel in 2 minutes" / "Build a Notion CRM in 6 slides" |
| **03** | **Native Format** | Personal photo + voice + story integrated into design | "How I [did X]" with your face/photo embedded |
| **04** | **Compilation Format** | List of items / rules / tools / examples | "Design GUIDE in 2026" / "10 viral hook formulas" |
| **05** | **Story Format** | Knowledge share with narrative arc (sets up problem, journey, lesson) | "How I got 37 logo design projects in 30 days" |

---

## Format selection decision tree

Ask the user:

> "Which format fits your topic?
> 1. **Comparison** — two things side-by-side
> 2. **Tutorial** — step-by-step how-to
> 3. **Native** — personal photo + story
> 4. **Compilation** — list/collection
> 5. **Story** — knowledge share with narrative arc
>
> Or describe your topic in 1 sentence and I'll suggest."

If user describes the topic, pick the format using these signal rules:

| Topic signal | Format |
|---|---|
| Contains "vs", "before/after", "wrong/right", "old/new" | **Comparison** |
| Starts with "How to" or "Steps to" | **Tutorial** |
| Contains "I", "my journey", personal pronoun + result number | **Native** or **Story** |
| Lists ≥ 4 items ("5 tips", "10 tools", "7 hooks") | **Compilation** |
| Tells a journey arc (problem → struggle → fix → result) | **Story** |
| Frame-shifts the reader's mental model | **Story** |

## Format → Slide structure mapping

Each format has a slightly different slide arc. Use these as starting templates — the 7-slide and 10-slide options below override the generic Hero → Problem → Solution → Features → Details → How-to → CTA arc.

### 01. Comparison Format

```
Slide 1   Hook       — "Bad vs Beautiful X"
Slide 2   Setup      — Why most people pick the wrong one
Slide 3   Side A     — The bad / common / outdated approach
Slide 4   Side B     — The premium / new / correct approach
Slide 5   Detail     — Why Side B wins (specific mechanism)
Slide 6   Examples   — 2-3 quick visual proofs
Slide 7   CTA        — Save / DM keyword / try yourself
```

**Visual signature:** Slides 3 and 4 use mirrored layouts (left/right columns). Color contrast between sides.

### 02. Tutorial Format

```
Slide 1   Hook       — "Build X in 2 minutes"
Slide 2   Confirm    — What you'll have at the end
Slide 3   Step 01    — First action
Slide 4   Step 02    — Second action
Slide 5   Step 03    — Third action
Slide 6   Step 04    — Fourth action
Slide 7   CTA        — DM keyword for the template
```

**Visual signature:** Numbered steps `01 / 02 / 03` in mono. Each slide one screenshot or one diagram. Light/dark alternation between steps.

### 03. Native Format

```
Slide 1   Hook       — Personal photo + bold claim ("$1.2K → $42K")
Slide 2   Confirm    — Reframe of the claim
Slide 3   Story      — Where I started / what was broken
Slide 4   Insight    — The shift / decision that changed it
Slide 5   System     — What I do now (concrete framework)
Slide 6   Receipt    — Specific number proof
Slide 7   CTA        — Personal photo + 1 action
```

**Visual signature:** Your face/photo on slides 1, 3, and 7. Branded backdrop. Narrative-led copy.

### 04. Compilation Format

```
Slide 1   Hook       — "10 X tools you need in 2026"
Slide 2   Confirm    — Why these matter / how I picked them
Slides 3-9  Items    — One item per slide (icon + name + 1-line)
Slide 10  CTA        — DM "LIST" for the full PDF
```

**Visual signature:** Rigid grid. Each item slide identical layout. Numbered prominently. Save-bait pattern.

### 05. Story Format

```
Slide 1   Hook       — "How I got 37 X in 30 days"
Slide 2   Setup      — Where I started, what was wrong
Slide 3   Inflection — The moment / decision that changed it
Slide 4   System     — What I built / changed
Slide 5   Result     — Specific outcome (number)
Slide 6   Lesson     — The transferable insight
Slide 7   CTA        — DM keyword to learn the full system
```

**Visual signature:** Narrative-driven typography. Personal photos on Hook + CTA. Numbers prominent on Result slide.

## Companion rules

### Slide template archetypes (3 categories per slide)

Every slide in any format falls into one of 3 template categories — apply the right rule per slide:

| Template | Where it appears | Rule |
|---|---|---|
| **Hook Slide** | Slide 1 always; sometimes slide 2 (confirm) | Bold scroll-stopper. Max 8 words. Display font 64–96px. |
| **Value Slide** | Body slides (3-9 typically) | Little text + lots of visuals. Max 14 words copy. One visual element max. |
| **CTA Slide** | Last slide always | Personal photo or logo + 1 simple action ("Save", "DM keyword", "Tag a friend"). NO swipe arrow. Progress bar 100%. |

### "Confirm the hook on Slide 2" rule (NEW from design.deb)

Slide 2's primary job is **NOT** to introduce the problem — it's to **confirm and amplify** the hook from Slide 1. Push the reader deeper before they bail.

Pattern:
- **Slide 1:** *"$300K. The wall 70% never break."* (hook)
- **Slide 2:** *"And it's not what you think. The reason isn't capacity — it's routing."* (confirm + push)

If you skip the confirm, you lose 30-40% of swipe-through. Slide 2 is the **second hook**, not the first body slide.

### "Consistent image style" rule (NEW from design.deb)

If the carousel uses generated/sourced images (Level 3), pick ONE image style and stick to it across all image slides:

- **Realism** — photoreal, cinematic
- **Illustration** — flat or painted illustration
- **Abstract** — geometric, gradient, atmospheric
- **Editorial photography** — magazine-style, high contrast
- **3D render** — modeled objects with consistent lighting

Mixing 2 styles in 1 carousel breaks brand cohesion. Krumzi 2026 benchmark: cross-style image carousels save-rate drops 40% vs single-style.

## How to use this file

When the user requests a carousel:

1. **Step 0 (intake):** ask "What format?" with the 5-option menu
2. **Or auto-detect** from topic signals (table above)
3. **Apply the format-specific slide arc** instead of the generic 7-slide arc
4. **Follow the slide template archetype** rules per slide (Hook / Value / CTA)
5. **Enforce "confirm on slide 2"** in every format
6. **Enforce "consistent image style"** if Level 3 images are used

If the user is unsure which format fits, default to:
- ≤ 5 items in a list → **Compilation**
- ≥ 5 steps with sequence → **Tutorial**
- Personal narrative → **Story**
- Two clear sides → **Comparison**
- Anything else with personal photo available → **Native**
- Generic / unclear → ask the user, don't pick yourself
